= Market Grove — shared market engine v0.4.0
:revdate: 2026-11-13
:status: Atrium 0.5.84 source candidate, not deployed
:toc:

This is the current game-owned exchange contract. Prior 0.2.0 maker-only rules are preserved in `SHARED_EXCHANGE_020_HISTORICAL.adoc` for provenance. The operator-specific integration guide is `../../../docs/ATRIUM_MARKET_GROVE_EXCHANGE_084.adoc`; Wallet trust contract is `TAVI_WALLET_STOCKS.adoc`.

== Ownership and intended experience

Market Grove is a game in Atrium: `atriumd.yaml` declares `game.id: market.grove` and LoopRD registers `games/market-grove/looprd.yaml` as a *subcomponent* of Atrium's existing root `looprd.yaml`. The child owns one persistent shared SQLite market with one order book per fictional instrument, positions, simulator accounts, reference observations and a global quote. Atrium discovers and launches the game; Tavi remains a messenger and Wallet/Gold authority. The browser has no private service credentials, operator grants, bank balances or independent exchange authority.

This is **not** a real securities, FX, metals, oil or cash market. Virtual trading is entertainment; no fiat deposits, cash-outs, buyable Gold, paid creator returns, withdrawals, wagering or financial incentives. No assets are tokenized or redeemable.

== Current implemented source behavior

* 44 globally shared instruments: 26 fictional equities, 12 commodity-inspired indices, six FX-inspired indices. Commodities and FX are perpetual finite game **units**, not rights to barrels, currency notes or physical assets. `XAUS` means simulated bullion and must not be confused with Tavi Gold.
* 20 deterministic trader strategies and 200 stable bot identities. Up to 20 bot intents are submitted for each live auction period. All bot orders are drawn from finite reserved *practice* credits and owned positions; they are canceled if unfilled at the next market tick, with holds released. No independent competing bot cron jobs are needed.
* Each source-backed account can place idempotent, bounded limit orders that hold cash or shares. Peer buy/sell orders receive maximum-volume matching, excluding same-owner matches. A uniform clearing price is selected inside a +/-12% reference-to-previous-price band; residual orders trade against a *finite* maker at the opening quote where eligible.
* All fills, holds, position transfers, maker inventory changes and fee transfers occur in one SQLite `BEGIN IMMEDIATE` transaction with the market period cursor. Bot replay, normal ticks and recovery after downtime do not re-run committed periods. No funds or shares are created by trading. Maker reserves are **practice balances**.
* Global prices are recomputed once per auction from executed peer prices, net executed maker flow, bounded deterministic game drift and a weak gravitation toward the reference valuation. Price changes are capped at +/-12% per interval. Unexecuted orders do not print fake trades or free spendable Gold.
* `market_references` distinguishes current game price, game reference, provenance, observed timestamp and asset class. An operator-only `market:reference` service imports explicit reference prices or raw external observations. The first raw observation fixes the unit normalization (e.g. oil dollars/barrel to *fictional* Gold units); subsequent relative changes adjust the reference, never the executed trade price directly. Stale, duplicate/conflicting or >15% unreviewed jumps fail closed.
* A new LoopRD child database defaults to a five-minute UTC auction period. Existing installations retain their immutable historical period (normally 3,600 seconds) without resetting holdings or migrating their schedule implicitly. The `clear-market` LoopRD scheduler checks once per minute and executes at most one catch-up market tick after downtime.
* `market:reference` is separate from `market:trade`, and is operator-only. No browser function calls it. The authorized importer `tools/market_grove_reference_import.py` has *dry-run* default and explicitly gated `--apply`. Fetching ECB data is opt-in with `--ecb`. EIA oil requires an operator-owned API key and approved feed; licensed metals must be independently approved. No remote feed is automatically trusted or fetched by the child.

== Ledger and integrity invariants

Invariant per symbol: `maker_shares + sum(all player and bot shares)` is constant absent an explicitly approved corporate action. Invariant for the whole demo market: `sum(players.cash) + sum(makers.cash) + trading_treasury.fees` is constant after accounts have been seeded. Cash held is a **reservation**, not a second balance to add to totals. Gold is always an integer amount and positions cannot fall below zero. Brokered real Wallet holds do **not** exist in 0.4.0.

No simulation-issued practice credits, maker funds, bot profits or reference-only portfolio gains are convertible into spendable Tavi Gold. This is crucial: setting `walletConnected: true` or swapping a currency ID is not integration. `TAVI_WALLET_STOCKS.adoc` gives the concrete service extension and failure-recovery requirements. Never use `wallet:reward` as an unlimited payout for synthetic market trades. Bot wallets may only become trusted Gold accounts after an explicitly funded, audited, realm-scoped operator allocation and approved new Wallet service contract.

== HTTP child API

[cols="2,3,2",options="header"]
|===
|Method |Path |Scope
|GET |`/market/state` |`market:read`
|GET |`/market/history` |`market:read`
|GET |`/market/activity` |`market:read`
|GET |`/market/investments` |`market:read` (practice projection only)
|POST |`/market/order` |`market:trade`
|POST |`/market/cancel` |`market:trade`
|POST |`/market/reference` |`market:reference` (operator only)
|POST |`/market/reference/observation` |`market:reference` (operator only)
|===

Reference observation example (private service request; no user/browser route):

[source,json]
----
{"symbol":"OILS","source":"eia-daily","observation":"82.51","observedAt":1794528000,"requestId":"eia_2026-11-13_OILS"}
----

`referencePrice` represents the normalized *fictional* Gold unit valuation; `price` is the actual current shared game quote. `premiumBps = (price - referencePrice) / referencePrice * 10000` is derived and never directly charged or credited. The client offers equity/commodity/FX filters, a reference-premium view, history, limit orders, existing practice portfolio and explicit non-Wallet labeling.
