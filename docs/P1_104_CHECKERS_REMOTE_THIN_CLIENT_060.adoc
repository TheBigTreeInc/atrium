== Host and client contract

`src/checkers_remote_client.mjs` exports `CheckersRemoteClient({transport, matchId, requestIdFactory})`. The host injects an authenticated `transport({method,path,body}) -> {status,body}`. The client never supplies seat, subject, issuer, profile, bearer, cookie, login grant or CSRF token. The operator's real Social/LoopRD host MUST separately validate the real account session, accepted original challenge, authorization, TLS/CSRF/CORS and rate limits. This source module cannot supply these services.

Operations are limited to `POST /games/checkers/matches/{id}/join`, `GET /games/checkers/matches/{id}`, `GET /games/checkers/matches/{id}/legal-actions`, and `POST /games/checkers/matches/{id}/moves`. No unsafe unbounded URLs or extraneous client identity fields. `sameOriginMatchTransport(fetch)` is a same-origin browser convenience: HTTPS deployment and a server-managed authenticated session must already be in place. A cross-origin Tavi app MUST use a separately reviewed, host-owned transport. The API returns server-owned revisions, board, turn, winner, and legal paths.

`move()` uses one unique request ID for each attempted move. If the response is lost after the server commits the turn, the client retains the **same** ID and body and allows an explicit `retryPending()`. Confirmed server rejections clear the pending move, and revision conflicts require a fresh authoritative read. A delayed status refresh cannot roll back a newer observed revision. No local rule evaluation or client-side winner calculation is performed.

`src/checkers_remote_view.mjs` provides `mountRemoteCheckers(root,client)` and `selectServerPath(actions,selection,square)`. It renders the server board and lets the user follow only returned legal-action paths. It supplies manual refresh and explicit uncertain-delivery retry controls. It is intentionally a library, not a published Pages game or active TaviX extension. Game rules remain on the server.
