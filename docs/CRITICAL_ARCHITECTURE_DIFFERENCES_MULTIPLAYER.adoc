= Atrium v0.5.6 — Critical Differences from the Shared Multiplayer Architecture
:revdate: 2026-10-18
:toc: left
:sectnums:

== Source documents and scope

This gap analysis is based on `ADJUSTMENT_ASYNC_GAMES_LOBBIES_AGENT_API.adoc`, `LOOPRD_GAME_PLAY_CONTRACT.adoc` and `END_TO_END_TEST_PLAN.adoc` provided for Life, LoopRD/DAPI, Social, Tavi, Atrium and OpenClaw. The uploaded documents describe a *planning candidate*, not deployed APIs. This pass starts the Atrium-side implementation by adding a strict, offline `looprd.game-play/v1` info validator and proposed Life fixture. It does NOT assert that Life exposes `/play/info`, that OpenClaw can play, or that Atrium can host Life.

== P0 — Game API is not implemented

* Requested: game-owned create, join, list_matches, get, legal_actions, act, end_turn, history and resume operations, with pinned deterministic engine and revision-aware idempotency.
* Current: Atrium v0.5.5 only has a pending sidecar registration candidate API; no game-play backend and no live game API certification.
* This pass: `src/game_play_contract.py` validates a proposed game-info response, its engine digest, declared operations and capability dependencies. `examples/life.game-play-info.proposed.json` is a non-deployed fixture with a dummy digest and `agentPlaySupported: false`.
* Remaining: Life owns implementation and tests API-01 through API-15. Do not move match state or action evaluation into Atrium.

== P0 — Authentication and multi-instance identity

* Requested: verified `(issuer, subject)` binding, game-scoped short-lived grants and separately authorized agent seat.
* Current: Atrium does not provide a Social grant exchange or authenticated match launch. LoopRD's local `ctx.call` does not cross remote runtimes.
* Remaining: Social/LoopRD define trust and grant verification, Life authorizes seats; Atrium consumes approved grants only. No user UUID is accepted as authentication by itself. Cross-runtime transport requires an explicit separately authenticated design.

== P0 — Durable asynchronous turn lifecycle

* Requested: SQL-persisted match, 60-hour or no-timeout policy, durable transactional outbox, recipient-bound Social inbox and Tavi push/recovery.
* Current: no implemented end-to-end turn delivery or background-host-independent Life match has been demonstrated in this Atrium package.
* Remaining: Life implements authoritative on-demand transitions and atomic outbox; Social handles deduplication/inbox; Tavi renders notifications. Redis cannot be the sole durable store. Verify TIME and NOTIFY tests from the supplied plan.

== P1 — Portable registration and deployment binding

* Requested: optional URL-free `atriumd.yaml` read at the same immutable revision as `looprd.yaml`, automatic announcement after activation, and reviewed Atrium deployment binding.
* Current: Atrium supports sidecar validation and operator-only pending candidate intake, but LoopRD does not yet automatically detect/announce sidecars.
* Remaining: LoopRD `SourceReader`/reconciler reads sibling sidecar after successful activation; optional failure must not disable the game. Atrium validates publisher, game origin, and logical `game-web` origin separately. Never embed server URL in either template.

== P1 — Hosted game launch and lobby presentation

* Requested: reviewed multi-asset hosted-web launch, generic create/join/continue, invitation handoff, current turn/deadline.
* Current: v1 sandboxed <=1 MiB HTML loader cannot host Life's multi-asset Pages build; no game-backed generic lobby or Social login.
* Remaining: reviewed external-first launch, no bearer tokens in URLs, game-authoritative lobby state and secure handoff. Static Pages must not contain operator credentials.

== P1 — Agent API certification

* Requested: OpenClaw uses the same game API with its own Social account and seat, no DOM requirement; support badge only after headless acceptance.
* This pass: validator rejects an agent-capable info response without required headless operations; it cannot certify deployment, credentials or gameplay. Fixture deliberately says false.
* Remaining: AGENT-02 through AGENT-04 and wrong-seat/retry tests must pass on a deployed game before Atrium publishes `agentPlaySupported: true`. AGENT-06 is the future cross-game reuse gate.

== P1 — Acceptance evidence

The supplied test plan separates API-01..API-15, AGENT-01..AGENT-06, TIME, NOTIFY and ATR test families. Keep those identifiers unchanged in implementation reports. Local tests prove only source-level validator behavior. Do not report runtime, Windows ZipRunner, deployed Social/Tavi, Redis outage or 60-hour clock simulation as passed without execution logs.

== Build order

. Agree on typed game-play schemas and Social grant trust, preserving existing LoopRD capabilities.
. Implement and verify Life game-owned durable match/action API and deterministic replay.
. Implement Social outbox/inbox delivery and Tavi turn deep links.
. Implement LoopRD optional sidecar reconciliation and Atrium reviewed hosted-web/lobby launch.
. Certify OpenClaw headless play and cross-runtime restart/outage acceptance.
