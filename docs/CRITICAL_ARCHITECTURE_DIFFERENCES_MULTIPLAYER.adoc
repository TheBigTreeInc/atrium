== Reading guide

This document deliberately distinguishes *what the user requested*, *what the inspected Atrium source implements*, *what is missing*, and *what the assistant proposes*. A proposal is not an approved requirement. The three upstream AsciiDoc documents bundled under `docs/upstream-*` are the planning baseline. Claims about other repositories are integration assumptions unless separately verified on their deployed versions.

== 1. Requested architecture (source-derived requirements)

* A multiplayer game owns match state, seats, rules, turns, deterministic evaluation, history and resume.
* Looprd/DAPI hosts the game API; the human host does not have to remain online between turns.
* A turn may remain pending for about 60 hours; notifications must survive process restarts and temporary delivery failures.
* Social/Tavi supply verified identity, messaging, recipient inbox and notification presentation, without owning game rules.
* Atrium supplies discovery, review, launch, lobby presentation and continue-game routing, not gameplay authority.
* OpenClaw plays via authorized game APIs, not a special privileged browser automation path.
* `looprd.yaml` remains portable; an optional `atriumd.yaml` sidecar describes game metadata without deployment-specific URLs.
* Preserve the upstream test IDs (API, AGENT, TIME, NOTIFY, ATR) and require deployed evidence before claiming cross-component acceptance.

|===

== 3. Missing implementation relative to the requested design

[cols="1,1,3,2",options="header"]
|===
| Priority | Owner | Required implementation | Acceptance
| P0 | Life | Persisted game-owned match state, authoritative legal actions, revision/idempotency, restart-safe resume | API-01..API-15 and TIME
| P0 | Social + Life + Looprd | Verified issuer/subject and scoped seat grants; explicit trust between remote runtimes | Wrong-seat and expired/revoked grant tests
| P0 | Life + Social + Tavi | Transactional turn-event outbox, durable inbox, retry/dedup and deep link | NOTIFY and outage/restart tests
| P1 | Looprd/DAPI | Read optional `atriumd.yaml` at the same resolved revision on activation/reconcile | Sidecar changes detected; absent/bad sidecar never stops game
| P1 | Atrium | Reviewed hosted-web launch, instance binding, lobby and continue-game UI | ATR tests, real Life launch
| P1 | OpenClaw + Life | Legal-action API and independent authorized agent seat | AGENT-01..AGENT-06
|===

== 4. Assistant recommendations — NOT approved requirements

[cols="1,3,3",options="header"]
|===
| ID | Proposed adjustment | Decision required
| REC-01 | Split universal multiplayer operations from turn-based extension capabilities, so non-turn-based games do not implement `end_turn`. | Agree on protocol compatibility/versioning
| REC-02 | Prefer server-evaluated actions with deterministic client prediction, rather than trusting client-generated receipts. | Select authoritative action model
| REC-03 | Standardize typed schemas for grant exchange, action errors, notification envelopes and launch handoff. | Ratify machine-readable contracts
| REC-04 | Certify advertised agent support only after deployed headless gameplay tests. | Decide certification policy and evidence store
|===

== 5. Work order and non-goals

. Freeze the requested shared API semantics; explicitly decide REC-01..REC-04 before treating them as normative.
. Implement Life's authoritative game-owned API and test restart/replay.
. Implement Social/Tavi grant, outbox/inbox and notification delivery.
. Add Looprd sidecar reconciliation and Atrium reviewed launch/lobby integration.
. Certify OpenClaw with real authorized turns and cross-game reuse.

No change in this Atrium pass implies that other components are deployed or that the proposed APIs are already live. The existing game engine, Social credentials and Looprd data are not migrated.
