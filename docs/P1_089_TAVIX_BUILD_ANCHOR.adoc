= Atrium 0.5.45 — TaviX staging guaranteed by npm build
:revdate: 2026-10-25

== Problem

ZipRunner observed `configured_count=5` build commands for 0.5.44 while its source `project.zr` described six, ending in `node tools/post_build_tavix.mjs`. An already-registered project may retain a previously configured command array and never execute newly appended commands. The local TaviX extension directory was not present, so prior assumptions about successful staging were not supported.

== Implementation

`npm run build` (already in both old and new recipes) performs, in order: `tools/build.mjs` (web), `tools/verify_web.mjs`, `tools/post_build_tavix.mjs`. The latter assembles TaviX 1.0.4 and invokes `tools/stage_tavix.mjs` with a mandatory Windows sibling path. The stage script verifies the target manifest, `.tavix` and repository index before reporting `TAVIX_STAGE_READY`. New .zr recipes omit the redundant stand-alone staging command. Repeated identical staging is immutable and no-op; TaviX's own repository.py remains the packaging authority.

Only GitHub-hosted CI (`GITHUB_ACTIONS=true`) can skip a missing Windows sibling checkout; explicit `TAVIX_STAGE_REQUIRED=1` always wins. Linux standalone source CI may skip unless explicitly required. No credentials, paths to active private state, Git commits or pushes are added to the archive.
