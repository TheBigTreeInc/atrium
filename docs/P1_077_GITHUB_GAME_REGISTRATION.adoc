== Status

Supersedes the v0.5.31 cross-repository workflow dispatch concept. A game does NOT receive a GitHub App token, Atrium workflow permission, or an Atrium registration secret. See link:GITHUB_PULL_GAME_REGISTRATION.adoc[full procedure].

== Game responsibility

* Publish a successful GitHub Pages release from a portable `looprd.yaml` and `atriumd.yaml` at the same immutable source revision.
* Optionally run the Atrium compatibility Action using its own repository's read-only `contents: read` credential; this is local validation only.
* No cross-repository events, grant or secret required.

== Atrium responsibility

* Approve each publisher / source / origin binding once through `registry/trusted-sources.json` review.
* `.github/workflows/receive-game.yml` runs on an Atrium-owned 15-minute schedule or manual dispatch. It discovers latest successful Pages deployments from approved public repos; `tools/sync_github_game_registry.py` revalidates fetched manifests and generates `registry/games/*.json` plus `web/hosted-games.json`.
* Its own `GITHUB_TOKEN` can update Atrium `main` where branch policy permits. Optional auto Pages publication uses **Atrium** repository variables and Atrium-owned workflow credentials only.
* New third-party repositories remain pending until an operator reviews trust and origin ownership; mere public compatibility does not approve games.

== Boundaries

This is eventually consistent; scheduled GitHub Actions may be delayed. Compatibility and Pages success do not certify Social identity, LoopRD match authorization or Tavi embedded launch. Disabled trust removes public snapshot only after an approved Atrium sync and Pages refresh.
