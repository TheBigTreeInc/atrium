== New module-owned host port

`src/checkers_trusted_host.py` adds the *non-networked* `CheckersTrustedHost` boundary around the existing durable `CheckersMatchAuthority`. It uses two required **server-owned** callables:

* `resolve_account(trusted_context)` must validate a real Social-owned account session and return a typed `VerifiedAccount(issuer, subject, audience)` with audience exactly `atrium.checkers/v1`. A user-supplied JSON subject/profile/seat is not such a callback.
* `approve_lobby(trusted_context, lobby_ref)` must query current original/accepted Social challenge/lobby authority and return `ApprovedLobby(match_id, game_id='checkers', status='accepted', red, black)`. A user-supplied acceptance flag, raw HTTP ticket or arbitrary client-approved lobby is never valid.

Issuer is configured by the host. The adapter validates issuer and audience on actor and both seats; requires actor to be an approved participant; and derives an internal SHA-256 seat key from the verified `(issuer, subject)` pair to avoid cross-issuer UUID collisions. **Hashes are lookup keys, not session credentials.** Match ID comes from the approved-lobby response, not a client-supplied participant or arbitrary requested match ID. Invalid binding, changed identity, declined/pending/cross-game lobby, outsider and duplicate creation fail closed.

After admission the port offers `inspect`, `join`, `legal_actions` and `move` with authenticated context, while the game-owned authority remains the only rules/revision/persistence component. The port does not create an HTTP listener, validate Social tokens itself, register a LoopRD handler or allow client-provided identity. A trusted operator must implement secure `resolve_account` and `approve_lobby`, including signature/audience/expiry/nonce/revocation checks and original accepted challenge verification, before activation.
