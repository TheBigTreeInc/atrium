== New operator-scoped endpoints

Each route requires `apps:approve`; none is anonymous and no credentials are accepted in request payloads.

* `POST /registry/publishers/proofs` with `{"publisherId":"studio-x","origin":"https://studio.example.org"}` issues a new challenge only for an already active, operator-approved publisher and one of its registered exact HTTPS origins.
* Response gives `challengeId`, `expiresAt`, `proofUrl` and `proofContent`. Serve exactly those UTF-8 bytes at `https://studio.example.org/.well-known/atrium-publisher-proof/<challenge-id>.txt`.
* `POST /registry/publishers/proofs/verify` with `publisherId`, `origin`, `challengeId` fetches and validates ownership. Success records `status=verified` but does not approve a publisher or game.
* `GET /registry/publishers/proofs?publisherId=studio-x` returns scoped status metadata and timestamps without the nonce or stored digest.

Issuing another challenge for the same publisher+origin invalidates the previous one. Each challenge has a 15-minute issuance-to-verification window and is consumed at first successful verification. The SHA-256 of the exact proof bytes is stored, not the plaintext nonce. Origins are unique across publisher-proof claims to avoid two publishers being verified for a single domain. Historical verifiedAt is *not* perpetual ownership assurance; reissue/reverify before security-critical changes.

== Network security boundaries

The verifier accepts only a canonical DNS-based HTTPS origin on TCP 443. It resolves DNS once per attempt, rejects the whole result when any address is non-global (loopback, private, link-local, documentation or special-use), connects directly to an approved numeric IP (no system proxy or DNS lookup at connection time), and sends a TLS request with SNI and CA-verified hostname. It does not follow redirects. Response must be HTTP 200, uncompressed, and at most 1024 bytes. Connection and response timeouts are 3 seconds each. Rebinding DNS cannot move the validated socket to a private address.

Failed DNS, TLS, HTTP or content checks never mark proof as verified. A successful outbound check must repeat the pending challenge and publisher status check in a database transaction before setting `verified`. A disabled publisher cannot obtain or complete a proof.

Network proof does not establish the *asset* SHA-256, trademark ownership, rights to a game, or a Social identity. Those remain separate review criteria.
