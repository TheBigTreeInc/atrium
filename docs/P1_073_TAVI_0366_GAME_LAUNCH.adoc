== Scope

The Atrium Tavi extension obtains `host.info.features`, requires `atrium.tavi-launch/v1` support, and calls `ui.requestGameLaunch` only after a fresh approved hosted-games catalog read. The response `awaitingApproval` is pending human approval, *not* evidence that a game opened. Tavi owns its confirmation UI and the actual external-navigation click. The iframe sandbox stays unchanged.

== Resume and credentials

The current hosted game projection contains an approved Life Pages origin but no authenticated `list_matches`/match-selection UI. To avoid inventing Life authorization, the Tavi extension asks for an *existing opaque match ID* when resuming. This identifier is never a token and does not authenticate its owner. Life must enforce game identity and seat on navigation and subsequent `/play` calls. This candidate does not create matches, redeem Social proofs or implement an authentication exchange. The standalone Atrium browser launch remains independent.
