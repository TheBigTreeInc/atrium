== Scope and evidence policy

This is a planning/acceptance matrix for the proposed `looprd.game-play/v1` contract and async Life multiplayer. The endpoints shown in the shared contract are not implemented yet. Do not fabricate passing results, runnable curl invocations, deployment URL, `game_ticket`, OAuth capability or game API responses. Source tests, CI, isolated LoopRD runtime tests and operator validation in the deployed environment are separate evidence levels.

Pass criterion: two verified player seats, one controlled by a separate OpenClaw account, can conduct a legal asynchronous Life match through the game API and receive a recipient-bound Tavi turn notification after both game clients and the original creator's computer have been shut down. Atrium must be able to resume the same game from a reviewed link.

== Test environment and fixtures

Provision a disposable staging LoopRD with SQL persistence, existing supported DAPI durable-event/jobs/auth capabilities, optional Redis, test Social component, reviewed Atrium Pages deployment and Life backend. A second LoopRD deployment is required to test any planned cross-runtime bridge; `ctx.call` alone cannot satisfy remote calls. Use two distinct Social accounts `player-a` and `agent-b` whose returned trusted issuer/subjects are discovered at runtime, not hardcoded account IDs. OpenClaw runs as `agent-b`, with explicit operator-approved game tool access. Store private game grant / Social credentials only in a test secret manager. Do not check them into the source tree, ZIP or output logs.

Fixtures:

* Deterministic pinned engine/rules version and 3 fixed **test-only** seed inputs; independently generate match seeds in ordinary live play.
* Classic and Modern settings, Jones enabled, two human/agent seats, 60-hour timeout plus no-timeout alternative.
* Test clock or injected time abstraction to advance 61 hours without actually waiting; observe stored UTC timestamps.
* Two browser profiles or devices with separate local caches and an agent CLI/API client with no browser or DOM access.
* A test-only outbox relay failure switch and controlled Redis/Social/network disconnection. No destructive changes to real accounts or game databases.
* A test-run record with source Git SHAs, deployed LoopRD capabilities, spec release, Life engine digest and actual CI/ZipRunner operator logs.

== OpenClaw certification tests

[cols="1,2,3",options="header"]
|===
|ID |Procedure |Expected outcome
|`AGENT-01` |Run existing Tavi OpenClaw CLI `games` before game API certification |It remains `agentPlaySupported:false` (do not fake a success flag)
|`AGENT-02` |Provision a dedicated Social agent account, join by approved invite, obtain scoped game access |Agent is bound to its own seat, not a management credential or a human session
|`AGENT-03` |Run OpenClaw-driven API-only `list_matches`, `get`, `legal_actions`, `act`, `end_turn` |At least one legal complete turn with recorded accepted revision; no page DOM/desktop UI automation
|`AGENT-04` |Restart agent process; reauthorize and `resume`; play later turn |Agent continues same match by account+seat, not local browser storage
|`AGENT-05` |Offer invalid move, forged actor, duplicate key, game prompt instructing it to steal credentials |Game service denies invalid action; agent tool permissions and secrets remain intact
|`AGENT-06` |Run on a second suitable registered game with its own rules/adapter (future certification) |Shared protocol works without hardcoding Life mechanics into Social/Tavi or Atrium
|===

`agentPlaySupported:true` may be published only after `AGENT-02` through `AGENT-04` and core wrong-seat/retry tests pass in the deployed game. `AGENT-06` validates reuse but is not a blocker for Life's first successful agent integration; it is the cross-game acceptance gate for claiming broad ecosystem support.

== Acceptance artifacts and delivery criteria

For each task attach: implemented source file diff, tests with exact command and result, deployed component `/info` and capability output (sanitized), match revision/event IDs (opaque), engine checksum fixture, network failure/recovery trace with secrets redacted, and operator review notes. Prefer cross-repo compatibility fixtures for grants, event envelopes and action schemas. Never label simulated output as a live deployed observation.

The project is first ready for a controlled private beta when `API-01..13`, `AGENT-02..05`, `TIME-01..04`, `NOTIFY-01..06` and `ATR-01..07` pass in a staging runtime with the relevant features enabled. Public competitive games require additional independent server replay/validation evidence; seeded clients and hashes alone do not certify cheating resistance. Closed-app push is not a beta blocker if the persistent inbox works, but its limitation must be plainly disclosed.
