= Atrium 0.5.51 — LoopRD 0.5.0 anonymous hosted catalog integration
:revdate: 2026-10-26

== Implementation

Atrium pins the generic LoopRD 0.5.0 source revision `abaf03fc2e97858508963cee23ba54fb5a041738`. It declares `requires: [auth.anonymous-read-handler.v1]` and opts exactly `GET /catalog/hosted-games` into `access: anonymous`; unlike the previous Atrium 0.5.50 route it carries **no scopes**. The parent component retains `auth.mode: database` and migration version 6. No other handler, resource, discovery receiver, management endpoint, job or WebSocket becomes anonymous. The source is produced by `tools/build_registry_spec.py` and validated by `tools/check_specs.py` and `tests/test_looprd_hosted_catalog.py`.

At runtime, the resulting route is `GET /looprd/atrium/v1/catalog/hosted-games` on the **operator's real API HTTPS origin**, routed by generic LoopRD. It reads fresh active `AtriumTrustedDeployment` and `AtriumTrustedInstance` data using `ctx.session_factory`; game title, publisher, active deployment, immutable Git revision and trusted HTTPS launch/API origins are projected into `atrium.hosted-games/v1`. The result is limited to 100 games and 256 KiB, contains no Social token or operator key, and fails closed on malformed trusted records and unavailable storage. Disabling or withdrawing a game removes it from the next result. No extra web server is required for the approved architecture. The historical loopback script remains as temporary migration fallback, not a deployment requirement.

== Platform requirements and verification

. Deploy and verify LoopRD **0.5.0 or newer with the exact generic capability** from pinned commit `abaf03fc2e97858508963cee23ba54fb5a041738`. This source update does not modify running LoopRD or grant deployment approval. The new Atrium descriptor should be rejected by an older strict runtime.
. Import `atrium-0.5.51-ziprunner.zip` and run `python tools/run_python_checks.py`, `npm test`, `npm run build`, `npm run verify` on the installed Windows project. Run the official pinned DAPI semantic validator and disposable migration/handler smoke. Do not mark completed based on source tests alone.
. Inspect the existing trusted deployment record using operator authorization; preserve **all** originRef mappings when changing `launchOrigins`, because the management action replaces the entire map. Bind `game-web` (Life) and any independently reviewed Market Grove launch origin to *real approved* immutable HTTPS release pages; set `atrium-web` if required by its registered sidecar. No URL or private key is embedded in `looprd.yaml`.
. Verify with an ordinary unauthenticated HTTP client: `GET https://<actual-api-host>/looprd/atrium/v1/catalog/hosted-games` must return 200 JSON with `schema: atrium.hosted-games/v1`, `Cache-Control: no-store`, `Access-Control-Allow-Origin: *` and no cookies or secrets. Browser preflight `OPTIONS` is handled by generic LoopRD. Verify POST and unrelated handler/management routes still demand their prior auth, and missing storage returns sanitized 503 rather than an empty success or stale cache.
. Verify Life appears only when source metadata, current instance state, API path and launch origin are all valid; disable/withdraw and restore it, rechecking subsequent GETs. Repeat for Market Grove when independently verified.
. Only after the real HTTPS endpoint passes preflight set `ATRIUM_PUBLIC_HOSTED_CATALOG_URL` to that exact complete URL and `ATRIUM_REQUIRE_PUBLIC_HOSTED_CATALOG=1` in the *operator's ephemeral build environment*, and stage the new **immutable TaviX 1.0.6** under independent TaviX review/publish controls. No build should overwrite installed 1.0.4/1.0.5. Confirm Tavi shows both games and withdrawal behavior. Social identity, Life seats and offline turn notifications are separate live acceptance tasks.

== Safety and rollback

Without real trusted launch origin mapping, the catalog may respond with zero games even when LoopRD reports Life active. This is expected fail-closed behavior, not a feature-completion signal. Roll back a faulty runtime generation via LoopRD's last-good-source policy; retain private DB and operator state and never downgrade schema. Avoid removing the anonymous declaration on a mixed runtime without testing client behavior and preservation of prior immutable extension releases. Do not treat successful source checks as deployment or QA approval.
