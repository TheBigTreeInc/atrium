== Test boundaries

* `tests/support/checkers_disposable.py` runs a loopback-only HTTP server on `127.0.0.1:0`. It uses a temporary SQLite file and delegates all American Checkers rules to `src.checkers_adapter.CheckersEngine` and `src.checkers`, the same files included in the ZIP. An injected *fixture-only* bearer-token map simulates two distinct verified subjects. No Social tokens, service credentials, network deployment or real identity integration exist here.
* `tests/test_checkers_group_qa.py` opens separate HTTP connections for red and black, validates sequential moves, mandatory chained captures, king promotion and victory, wrong-turn, unauthorized identity, duplicate changed payload, stale revision, illegal moves, and server restart with durable state and exactly-once retry response.
* Neither generic Atrium lobby nor catalog implements game rules. The `modules/games/checkers/looprd.yaml` current stateless rules-oracle is unchanged; the new test server is deliberately *not* linked into root `looprd.yaml`, Tavi, or any public API. Generic LoopRD/DAPI validation and the game module's real deployment are separate future acceptance steps.
* Report uses bounded test-group assertions, deterministic initial-state fixture SHA-256, version and a composite hash of exact tested rules/QA files. A skipped, missing or failed test makes the report fail; source-tree mode is never reported as exact-ZIP mode.

CI also uploads one report per Linux/Windows source run; those have `scope=SOURCE_TREE`, not exact ZIP.
