= Atrium Project Plan
:revnumber: 0.4.0
:toc: left

== Product intent
Independent browser/Tavi-accessible app and classic-games ecosystem with a dynamic registry, reusable game engine, social access and clearly labeled Staff opponents. Looprd defines the component format and DAPI executes it.

== Current outcome
P0 v0.3.0 foundation is present in the GitHub repository. P1 v0.4.0 provides the first persistent, scoped, operator-reviewed app registry in source. It is an incremental candidate update to ZipRunner project `atrium`, *not* a deployed release.

== Lifecycle rules
Development reports describe source evidence only. ZipRunner's trusted verification and the operator's real acceptance tests govern the managed task state. The operator must approve push, release, migration and deployment separately. Historic tasks must be retained by their original IDs; build failure never marks work Done.

== Approved access and distribution direction (design v0.5.0)

GitHub Pages hosts the standalone Atrium portal with Looprd APIs elsewhere.
Users register once in Social. Direct Atrium sign-in is through a reusable
Social-owned web authentication interface; launching from Tavi uses the same
identity with a trusted one-time exchange. Tavi remains the chat app; Atrium
owns game discovery, launch, installation and per-platform compatibility.
This planning update introduces no working sign-in, installer or backend API.
See `docs/PLATFORM_ACCESS_AND_INSTALLATION.adoc`.

== v0.5.1 — First external game registration contract

The approved direction for independently hosted games, Life/Jones as first candidate, platform-aware registration and a future optional `atrium.host/v1` integration adapter is documented in `docs/GAME_REGISTRATION_AND_HOST_SDK.adoc`. Current `atrium.app/v1` still requires an operator-approved <=1 MiB immutable HTML entry; Life's current offline HTML is too large and its multi-asset Pages site needs a separately reviewed hosted-site launch mode. `examples/life.atrium-game-v2.example.json` is a design fixture, not importable current registry data. This v0.5.1 pass **only documents and regression-tests the contract**. No v2 service, real Life publication, Social login, SQL migration, SDK or installer is claimed.


== Looprd-native discovery: activation is not Atrium registration (v0.5.6)

The game-owned Looprd `looprd.yaml` can expose a normal read-only discovery handler, but the root Looprd descriptor cannot add an unrecognized `atrium:` field. Atrium learns the game endpoint through a scoped deployment-side announcement (for an admitted local component) or a reviewed external publisher registration; the deployment reconciler and Atrium discovery API are proposed and **not implemented** in v0.5.6. A discovery hit becomes a pending reviewed registry candidate, never automatic publication or backend activation. The game's Looprd database, session tokens and verified Social account principal remain game-owned. The existing Life service has public room-token auth; shared verified Social principal adoption is separate work. Full source: `docs/LOOPRD_GAME_DISCOVERY.adoc`.
